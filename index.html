Give PRAGMATA the complete HDR path.

PRAGMATA needs more than an HDR-capable monitor. Wine must report a 10-bit Advanced Color display, Gamescope must expose HDR Vulkan formats, and the compositor must drive the display in HDR.

Keep Proton on Xwayland

Do not set PROTON_ENABLE_WAYLAND=1 for this procedure. Valve’s X11 driver propagates the HDR monitor state PRAGMATA checks; native Wine Wayland does not currently provide the equivalent path.

Procedure

Set up the whole chain

Use official packages and an official Proton build first. Custom Proton builds add another variable when diagnosing display behavior.

01

Prepare Steam and the display

  • Enable HDR in the monitor’s own controls.
  • Install current Steam, Gamescope, Mesa/Vulkan drivers, and Vulkan tools.
  • In Steam → PRAGMATA → Properties → Compatibility, select official Proton Experimental or Proton 11.
  • Close any Steam client already running on the desktop before starting the standalone session.
02

Find the connected DRM output

Connector names differ by GPU, port, and machine. Read the live DRM state instead of copying someone else’s DP-1.

Shell
for status in /sys/class/drm/card*-*/status; do
  printf '%s: %s\n' "$status" "$(cat "$status")"
done

Use the connected connector and a mode your display supports. Start at a conservative refresh rate if the maximum mode causes link loss.

03

Start standalone HDR Gamescope

Save your work, switch to another virtual terminal such as Ctrl+Alt+F2, and log in. Then substitute your connector and mode:

Canonical launch
DXVK_HDR=1 \
ENABLE_HDR_WSI=1 \
ENABLE_GAMESCOPE_WSI=1 \
gamescope \
  --backend drm \
  --prefer-output <connector> \
  -W <width> -H <height> \
  -r <refresh> \
  -f -e --hdr-enabled \
  -- steam -gamepadui
Example: 4K 120 Hz on DP-1 
DXVK_HDR=1 ENABLE_HDR_WSI=1 ENABLE_GAMESCOPE_WSI=1 \
gamescope --backend drm --prefer-output DP-1 \
  -W 3840 -H 2160 -r 120 -f -e --hdr-enabled \
  -- steam -gamepadui
04

Launch PRAGMATA inside that Steam session

Open PRAGMATA from the Steam interface running inside Gamescope. This makes the game inherit the HDR variables and Gamescope socket. Open the game’s display settings and enable HDR.

When finished, exit PRAGMATA and Steam. Gamescope should return you to the terminal. Switch back to the desktop VT with Ctrl+Alt+F1 or the VT used by your desktop.

Three switches

Each controls a different layer

DXVK_HDR=1

Windows display state

On Proton’s Xwayland path, this lets Wine report the synthetic Windows monitor as HDR-capable. PRAGMATA’s Advanced Color query can then return supported, enabled, and 10 bits per channel.

ENABLE_GAMESCOPE_WSI=1

Vulkan HDR formats

Activates the Gamescope WSI layer that exposes HDR10/ST.2084 surface formats and forwards HDR metadata from the Vulkan client.

--hdr-enabled

Physical HDR output

Tells Gamescope to drive its selected DRM output in HDR. Without it, an HDR client may be tone-mapped back to SDR.

ENABLE_HDR_WSI=1 is included for compatibility with Proton/Gamescope HDR launch conventions used by current installations.

Evidence

Verify all three layers

A brighter image alone does not prove that the game created an HDR swapchain.

A

Display

The monitor enters its HDR mode. This confirms the output signal, not yet the game’s swapchain.

B

Gamescope

The terminal identifies the intended connector and prints HDR output enabled without DRM-master or fallback errors.

C

Windows API and game

PRAGMATA offers HDR. A deeper Wine probe of DISPLAYCONFIG_DEVICE_INFO_GET_ADVANCED_COLOR_INFO should report support and enablement with 10 bits per channel.

Expected Advanced Color state 
advancedColorSupported = 1
advancedColorEnabled   = 1
bitsPerColorChannel    = 10

Diagnostics

When the chain breaks

PRAGMATA still says HDR is unsupported

Confirm the game process inherited DXVK_HDR=1, ENABLE_HDR_WSI=1, and ENABLE_GAMESCOPE_WSI=1. Use official Proton 11 or Experimental, remove PROTON_ENABLE_WAYLAND, and launch the game from the Steam instance inside Gamescope.

Gamescope cannot acquire the seat or DRM master

Run it from a real local VT with an active login session. Ensure another compositor does not still own the target output and that your distribution’s logind or seatd setup grants access to DRM and input devices.

Black screen or connector not found

Rediscover the live connector. Test a lower refresh rate such as 60 or 120 Hz before changing drivers. Check that resolution, bit depth, cable, and port fit within the link bandwidth.

HDR looks washed out

Confirm PRAGMATA actually enabled HDR rather than presenting SDR content inside an HDR output. Check full/limited range and monitor tone-mapping settings. Do not use --hdr-debug-force-support as proof; it can advertise support while the final output remains SDR.

The game opens on the normal desktop

The wrong Steam process handled the launch. Exit desktop Steam, start Steam inside standalone Gamescope, then launch PRAGMATA from that instance.
